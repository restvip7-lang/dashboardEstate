# STAYPROPERTY — дашборд директора

Управленческий дашборд для телевизора в кабинете директора. Два режима — **Агентство** (продажи) и **Застройщик** (портфель из 22 проектов) — сменяют друг друга автоматически. Язык интерфейса: RU / EN.

Сейчас дашборд работает на **демонстрационных данных**. Реальные названия проектов, остальное вымышлено. Концепция, правила расчёта и открытые вопросы описаны в [`docs/dashboard-concept-analysis.md`](docs/dashboard-concept-analysis.md).

## Онлайн-версия

**https://restvip7-lang.github.io/dashboardEstate/**

Сайт работает на GitHub Pages и обновляется сам при каждом пуше в ветку `claude/charming-gates-qp7dvr`. Порядок такой: [workflow](.github/workflows/deploy-pages.yml) прогоняет тесты, собирает дашборд и публикует его. Если тесты упали, публикация не происходит. Статус смотрите на вкладке **Actions** репозитория.

> Репозиторий и сайт **публичные**: ссылку может открыть любой, кто её знает. Сейчас там только демо-данные. **Реальные финансовые данные в этот репозиторий класть нельзя.** Для них понадобится закрытый источник, например защищённый адрес, переданный через `?data=`. Это решается на этапе подключения данных.

## Запуск на своём компьютере

Нужен Node.js 20 или новее.

```bash
npm install
npm start          # собирает и открывает дашборд в браузере на http://localhost:4173
```

Для разработки: `npm run dev`.

Собранная версия (`npm run build`) лежит в папке `dist/`. Это обычные статические файлы: их можно выложить на любой хостинг. Открыть `dist/index.html` двойным щелчком нельзя: браузер не даст загрузить файл данных с диска. Нужен сервер — `npm run preview` или хостинг.

## Показ на телевизоре (ноутбук → HDMI)

1. Подключите ноутбук к Samsung по HDMI. В Windows выберите «Расширить» (Win+P), а не «Повторять». Тогда пропорции экрана ноутбука не повлияют на картинку.
2. Перетащите окно браузера на телевизор и нажмите **F** или F11, чтобы развернуть его на весь экран.
3. В настройках Samsung:
   - «Изображение → Размер картинки → По размеру экрана» — иначе края обрезаются;
   - режим «Игра» или «ПК» — так текст чётче.
4. Отключите сон и заставку ноутбука.

Экран нарисован на холсте 1920×1080 и масштабируется под любое окно. На 4K он просто увеличивается в 2 раза.

## Управление

| Действие | Клавиша / презентер |
|---|---|
| Следующий / предыдущий экран | → ← (также PageDown / PageUp — кнопки презентера) |
| Пауза / продолжить | Пробел, B или «.» |
| Сменить язык | L |
| Сменить режим Агентство ↔ Застройщик | M |
| Перейти к экрану 1–4 | 1, 2, 3, 4 |
| Полный экран | F |
| Закрыть карточку | Esc |

Мышью можно:
- кликнуть по плитке «Дебиторка по комиссии», пункту «Внимания директора», строке проекта или «Просроченным платежам» — откроется детализация;
- переключать режим и язык в шапке;
- переходить между экранами по точкам внизу.

Пока открыта карточка, автопрокрутка стоит. Через 2 минуты без действий карточка закрывается сама. Курсор прячется через 3 секунды.

Параметры ссылки: `?lang=en`, `?screen=3`, `?interval=30` (секунд на экран, по умолчанию 25), `?autoplay=0`, `?data=<адрес JSON>`.

## Экраны

1. **Результаты агентства**: комиссия за месяц, получено, объём продаж, дебиторка, план/факт по месяцам, лидеры, структура продаж, страны покупателей, «Внимание директора».
2. **Структура и команда**: штат, доход на менеджера, ставка комиссии, матрица «новостройка/вторичка × наши/сторонние», рейтинг месяца и лидер года.
3. **Портфель застройщика**: поступления к плану, продажи, остаток к продаже, риск задержки, таблица стройки (сначала проблемные), ближайшая передача, «Внимание», просрочка покупателей.
4. **Стройка: все проекты**: все строящиеся проекты по 7 на страницу, карточка проекта по клику.

Аренда пока не показывается: по решению владельца она будет отдельным режимом позже.

## Данные

Дашборд **не хранит готовых цифр**. Все показатели считаются из сырых записей: сделок, платежей, графиков оплат, отчётов стройки, юнитов, планов. Поэтому итоги, графики и разбивки всегда сходятся.

- Схема данных: [`src/data/types.ts`](src/data/types.ts). Это контракт для будущих источников: Битрикс24, выписок банка, таблиц стройки.
- Правила расчёта: [`src/metrics/`](src/metrics).
  - Сторно отмен идёт в месяце отмены.
  - Просрочка считается по графику оплат с льготным периодом: 15 дней для комиссии, 7 дней для покупателей.
  - Ожидаемый темп плана считается по рабочим дням.
  - Готовность считается по весам этапов, план — по утверждённому графику.
  - Статус проекта: «риск» — отставание больше 3 п.п. или прогноз позже срока; «задержка» — больше 7 п.п. или сдвиг больше 60 дней.
  - Отчёт стройки старше 10 дней помечается как устаревший.
- Проверка качества: [`src/data/validate.ts`](src/data/validate.ts). Проверяются дубли ID, ссылки между записями, доли менеджеров, двойная загрузка платежей и даты позже «данных на». Число найденных проблем видно в подвале экрана.
- «Внимание директора» формируется правилами из [`src/metrics/attention.ts`](src/metrics/attention.ts). Ответственного и действие берут из реестра `issues`. Если их нет, на экране так и написано: «ответственный не назначен».

Демо-данные создаёт `npm run demo-data`: скрипт [`scripts/generate-demo.ts`](scripts/generate-demo.ts) записывает `public/data/demo.json`. Генератор детерминированный: при каждом запуске получается один и тот же файл.

Чтобы перейти на реальные данные, подготовьте JSON той же формы и укажите его адрес через `?data=`. Экраны менять не нужно.

## Структура

```
src/
  data/        схема данных и проверка качества
  metrics/     расчёт показателей (чистые функции) + тесты
  i18n/        тексты RU/EN и форматирование чисел
  components/  шапка, подвал, кольца, график, таблица стройки
  screens/     экраны и выезжающие карточки
scripts/       генератор демо-данных
docs/          анализ концепции
```

Логотип сейчас нарисован по рендеру (`src/components/common.tsx`, компонент `Logo`). Официальный файл логотипа можно подставить, когда он будет.
